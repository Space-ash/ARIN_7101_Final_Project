## 复核方法与范围

1. 先仅用 `question` 与 `public_history` 确定最近 focus、目标项目与规范属性；另一条文本追踪路径提取事实陈述，不调用 M1 的解析器、生成器或 `audit_truth` 推导十题真值。
2. 逐条检查公开历史 ID 为 `0` 至 `end-1`。以最后一次目标事实陈述作为证据，连续同值陈述只前移证据，不增加旧值。推导完成后再与保存的 `gold/evidence/old_values` 比较。
3. 根据完整公开前缀中的 focus 与问题目标核对 `qtype`；本批每对话 300 题，abrupt 在 `t=150` 进入 B，stable 始终 A。状态变化影响题型抽样概率，不要求 B 的每道题都为历史题。
4. 对每条策略记录，只用其 `context` 重新解析指代与答案；检查消息文本逐条来自当前公开前缀，ID 唯一升序且与 `selected_ids` 一致。窗口另按连续后缀和预算重算。检索完整重选由现有开发回读脚本核对，最新证据的消解检索排名另用公开前缀重新拟合 TF–IDF 后核对。
5. 按正则 `\w+|[^\w\s]` 重新计数。预算只约束上下文正文；完整成本计入共同指令、格式、正文和问题。按重建真值核对 `y`、`coverage`、`outdated` 与 `utility = y - 0.5 × cost / 512`，再与归档行比对。
6. 运行 `python scripts/verify_m2_development.py`，通过 7,200 行、1,800 题及四十条审计策略记录的回读与重建检查。十题独立文本追踪与逐臂检查也全部通过。构造耗时不要求跨运行完全相等。

这些检查针对当前十题与开发归档一致性，不证明正式效果、最优策略或人工验收完成。原始 M1 run 的交接属于另一项待接收工作。
