# 成员主导的研究与协作
release只给任务与接口，不交付完整实现。每人必须有编码、自己设计的测试、研究解释和交接证据，运行成功不等于研究完成。

## 并行起步
M1做可追踪微型历史；M2用自建历史开发策略；M3用合成小表开发学习器；M4设计配对/聚合手算案例；M5用标为fixture的小表探索图型。示意数据不混入真实结果。

责任区间为m1-*至m5-*，共享设施变更由M4通知全组。每人记录自己的推导、选择、尝试、失败与修正，不只保留最终代码。

## 交接
| 交接 | 交付 | 接收人复核 |
|---|---|---|
| M1→M2 | 微型episode、字典、生成器、真值核查 | 输入检查，追踪一题证据 |
| M2→M1 | 10题公开历史、四臂上下文/回答/成本 | M1独立追踪，M2交叉审查，逐题留解释 |
| M2→M3 | 单对话全臂表、cost定义 | 字段/唯一键、信息边界 |
| M3→M4 | 学习器/回放、推导/数值检查 | 单对话重放、seed/重置/反馈 |
| M1–M3→M4 | 实现、测试、问题关闭记录 | 小规模demo联调，满足条件才冻结 |
| M4→M3/M5 | 完整run、统计、manifest、commit | M3复核统计，M5新内核独立校验读取 |
| M5→全组 | 自写图表及数据对应、解释、汇报 | 各人复核本人负责的图与结论 |

验收方向不是现成测试答案。成员自行构造能发现错误的案例；反馈指出seed/t、输入、预期性质、实际观察与修复责任人。

## 阶段
1. 写实现/测试计划；M5同步写叙事骨架。
2. 各自编码研究；M1/M2双人10题审查，M3推导和数值验证。
3. M4自行写运行入口集成demo；M5自行写读取器和绘图。
4. 全组确认协议与未使用seed。M4实现审查核验、冻结快照、哈希与登记；不是由工具代替全组签名。
5. 正式60条独立对话，保留正负结果/失败/已看记录。算法seed不是新增独立样本。
6. M3复核统计，M5核对图表，全员写真实解释并完成汇报。

参考本测试seed区间20261105…20261134与20261205…20261234不得作为新正式数据。M4也要记录其他已用seed。formal_runs.json当前为空；实现正式入口时登记尝试，禁止删除失败记录后反复挑seed。

## 探索空间
生成细节、平局、数值实现、失败处理、测试设计、图型可在开发阶段比较。影响下游的改动写interface_decisions.md，说明原因、影响与接收人确认。正式结果之后的修正/敏感性分析另标，不能冒充原主检验。

成员自行读课件和原始资料、推导和引用。参考本只作背景；借鉴须记录来源、自己的理解/修改/验证，不能把复制运行当个人贡献。

## Git与完成标准
每人分支只改本人区间；M4逐份合并，后续成员同步后再改，不能整本覆盖。提交前清输出并结构检查；实际研究测试由各成员实现，并在PR记录案例/命令/观察。

todo → doing → review → done：有本人实现、测试、解释及接收人确认才done。blocked需写缺失输入与责任人。程序不自动更新状态。输出归档被Git忽略，交接须给完整run、地址和校验和，不只发截图。
